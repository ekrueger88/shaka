# Understanding usage and cost reports

Expand **Shaka metrics → Usage and cost** for the reported model work and its
estimated cost. Read the coverage note before comparing totals. Missing values
mean unknown, not zero; dollar estimates are not an invoice.

```text
Explain which work this PR's costs cover, what is missing, and whether reports overlap.
```

## What the columns mean


| Column | Meaning |
| --- | --- |
| Report | Model and contribution, such as implementation or review. `×5` means five reports share that row. |
| USD | Estimated list-price cost, Pi's recorded nominal cost, or OpenRouter's reported account charge. Read each report's pricing note; the mixed total is not an invoice. |
| Codex credits | Estimated OpenAI Codex plan credits, separate from the USD estimate. |
| Input | Tokens sent to the model. Hosts differ in whether cached tokens are included. |
| Cached input | Input read from the prompt cache. Supported rate cards price cache reads separately from uncached input. |
| Output | Tokens generated by the model. Several hosts include reasoning in this count. |
| Reasoning | Tokens reported as reasoning. This can be a subset of output; do not add it again. |
| Cache writes | Input stored in the prompt cache for reuse. |

Rows group implementation, review, integration, and shared planning. `×5` means
five reports share a row. Empty columns are omitted. `—` means unreported.
`+` marks a lower-bound estimate when usage or prices are missing, or when
earlier reports appear below and are excluded from the total. Counts are rounded;
`45.3M` means about 45.3 million tokens.

The total adds cost and credit estimates, not tokens, because hosts count tokens
differently. Reports can overlap and count a response twice. A `+` marker does
not establish that reports are disjoint.

## Compare host counters carefully


| Host | Input accounting | Output accounting |
| --- | --- | --- |
| Codex | Includes cached input | Includes reasoning |
| Claude Code | Excludes cache reads and writes | Includes reasoning |
| Cursor | Includes cache reads and writes | Reasoning is unreported |
| OpenCode | Excludes cache reads and writes | Reasoning is counted separately |
| Pi | Excludes cache reads and writes | Includes reasoning |
| OpenRouter | Includes cached input | Includes reasoning |

For example, a Codex row with 100,000 input tokens and 80,000 cached input
tokens has 20,000 uncached input tokens. A Claude row with 20,000 input tokens
and 80,000 cached input tokens describes the same input quantities.
Do not add a Codex row's cached input to its input again.

## How estimates are priced

Rate-card estimates name their verification date and source links. Carrying a
report to a later revision preserves its pricing note and estimate; current
prices may differ.

OpenAI rows distinguish Codex plan credits from API-equivalent USD. Cursor uses
on-demand list prices. Anthropic prices uncached input, cache reads, and cache
writes separately; cache duration and fast mode can affect the rate. Pi keeps
its recorded nominal cost. OpenRouter uses the response's reported account
charge rather than direct DeepSeek list prices.

Unsupported models or incomplete billing categories stay unpriced. A partial
estimate shows the known amount, a `+`, and the reason. An incomplete review may
still cost money; a timeout without response metadata has unknown per-call cost.
Cost does not establish that review completed.

## Keep usage when work changes hands


Usage saved as comments on the PR survives a change of model or coding tool. A new owner
reads those comments instead of the earlier machine's records, and each response counts
once even if two agents saved it. Comments from accounts without write access are ignored.

Ask the agent:

> Save this task's usage on the PR before handing it over.

## Read the limitations beside the numbers

**PARTIAL** means the native records do not establish complete task usage.
The report states its selected interval and whether reviewer or tool usage
was included. Cursor reports exclude subagents. **UNKNOWN** means available
records do not establish a value or attribution.

For example, “implementation spans five rebased commits; per-commit allocation
is unavailable” permits a task estimate, but does not establish each commit's
cost. Historical reviews retain the commit they reviewed; they do not become
reviews of the latest revision.

[PR verification](../pr-verification.md) explains how to assess the change and its evidence.
